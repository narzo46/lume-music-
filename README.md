# Luma Music Universal

## Платформы и совместимость

Luma Music Universal поддерживает максимально широкую линейку старых и новых операционных систем при строгом соблюдении правила: платформа считается поддерживаемой только после успешной сборки и проверки на реальном или эмуляционном окружении.

## 1. Цели совместимости

- Поддержка Android, Windows и Linux на максимально широком диапазоне версий ОС.
- Сохранение совместимости со старыми платформами без ущерба безопасности, стабильности и качеству работы.
- Модульная архитектура, позволяющая обновлять поддержку платформ без переписывания основного приложения.
- Использование отдельных сборок для старых и новых систем там, где это необходимо.
- Автоматизация сборки и проверки через GitHub Actions.
- Явное указание в документации минимальной версии ОС, поддерживаемых архитектур и статуса проверки.

## 2. Общие принципы совместимости

- Минимальные версии ОС, архитектуры и зависимости должны проверяться при каждом релизе.
- Для старых систем применяются отдельные сборки, совместимые зависимости и специальные настройки, если современные стек и библиотеки их не поддерживают.
- Безопасность и стабильность имеют приоритет над совместимостью ради совместимости.
- Поддержка платформы не обещается, если приложение не собрано и не протестировано на ней.
- Для каждой платформы указывается статус: Поддерживается, Проверяется, Экспериментально, Не поддерживается.

## 3. Android

### Поддержка
- Минимальная версия: Android 7.0
- Поддержка всех актуальных версий Android, включая Android 16 и последующие релизы
- Поддержка современных смартфонов, планшетов и складных устройств

### Архитектуры
- ARMv7 (32-bit) — поддержка, где это технически возможно
- ARM64 (64-bit) — обязательная поддержка
- x86/x64 — при необходимости для эмуляторов или специализированных устройств

### Форматы сборки
- APK — основной формат
- AAB — при необходимости для публикации в Google Play

### Требования и особенности
- Адаптация под актуальные требования Android к разрешениям, фоновой работе, уведомлениям, энергосбережению и безопасности
- Поддержка фонового воспроизведения и корректной работы в фоне
- Поддержка уведомлений, медиа-сервисов и системных ограничений на энергопотребление
- Проверка совместимости с будущими версиями Android до их выхода

### Статус
- Поддержка считается подтверждённой только после успешной сборки APK и проверки запуска

## 4. Windows

### Поддержка
- Windows 7
- Windows 8
- Windows 8.1
- Windows 10
- Windows 11
- Поддержка будущих версий Windows по мере их выхода

### Архитектуры
- x64 — основной приоритет
- x86 (32-bit) — поддержка, где это возможно
- ARM64 — поддержка, где стек и зависимости совместимы

### Форматы сборки
- EXE — основной формат
- MSI — при необходимости
- Портативная ZIP-версия — при необходимости

### Требования и особенности
- Для старых версий Windows используются отдельные совместимые сборки и зависимости
- Проверка совместимости с новыми Windows-версиями и обновлениями безопасности
- Не использовать устаревшие или небезопасные методы только ради совместимости со старыми системами
- Учитывать ограничения безопасности, прав доступа, обновлений ОС и работы с Win32/Win64 API

### Статус
- Поддержка Windows подтверждается только после сборки EXE и проверки запуска на целевой версии ОС

## 5. Linux

### Поддержка
- Старые 32-битные Linux-системы, если стек и зависимости реально совместимы
- Современные 64-битные системы
- Основные дистрибутивы:
  - Ubuntu
  - Debian
  - Fedora
  - Linux Mint
  - Arch Linux

### Архитектуры
- x86
- x64
- ARM64

### Форматы сборки
- AppImage
- Flatpak
- DEB
- RPM

### Требования и особенности
- Учитывать различия между системными библиотеками и версиями glibc/libstdc++
- Поддержка различных аудиосервисов и системных интерфейсов
- Проверка работы под X11 и Wayland
- Поддержка различий между пакетными форматами и требованиями дистрибутивов
- Учитывать зависимости менеджеров пакетов и системных прав

### Статус
- Поддержка Linux подтверждается только после сборки и проверки конкретного пакета на целевом дистрибутиве

## 6. Модульная архитектура совместимости

Для поддержания широкого диапазона ОС и архитектур проект должен строиться по модульному принципу:

- Ядро приложения:
  - логика воспроизведения,
  - медиатека,
  - управление аудио,
  - UI-логика,
  - бизнес-логика
- Платформенные адаптеры:
  - AndroidAdapter
  - WindowsAdapter
  - LinuxAdapter
- Компоненты системной интеграции:
  - разрешения,
  - уведомления,
  - фоновые сервисы,
  - аудио-API,
  - энергосбережение
- Компоненты совместимости:
  - проверка минимальной версии ОС,
  - проверка архитектуры,
  - fallback-логика для старых систем,
  - разные зависимости для новых и старых платформ

Такой подход позволяет обновлять поддержку конкретной платформы без переписывания ядра приложения.

## 7. Проверка зависимостей и минимальных версий

Перед поддержкой каждой платформы должны быть проверены:

- минимальная версия ОС,
- минимальная версия SDK / компилятора,
- минимальная версия системного API,
- поддерживаемые архитектуры CPU,
- совместимость сторонних библиотек,
- наличие системных зависимостей,
- корректная работа аудиосервисов,
- совместимость с пакетами и окружениями

Если платформа не собирается или не запускается, она не считается поддерживаемой.

## 8. Автоматизация сборки и тестирования

GitHub Actions должен обеспечивать:

- отдельные сборки для Android, Windows и Linux,
- отдельные проверки для x86/x64/ARM64,
- сборку старых и новых систем отдельно,
- сборку AppImage, DEB, RPM, Flatpak, APK, EXE,
- проверку запуска и базового воспроизведения,
- регрессионное тестирование после обновления зависимостей,
- автоматическое уведомление о сбое сборки на одной из платформ.

## 9. Поддержка будущих версий ОС

- Для новых выпусков ОС заранее выполняется проверка совместимости.
- Анализируются изменения API, безопасности, системных требований и графических/аудио-стеков.
- При появлении конфликтов с зависимостями обновляется конфигурация сборки.
- Если новая версия ОС ломает старую сборку, используется отдельная совместимая ветка или конфигурация, а не ломается основная поддержка.

## 10. Статус поддержки по платформам

В README обязательно должны быть указаны:

- минимальная версия ОС,
- поддерживаемые архитектуры,
- формат сборки,
- статус проверки,
- дата последней проверки.

Пример:

- Android
  - Минимальная версия: Android 7.0
  - Архитектуры: ARMv7, ARM64
  - Формат: APK, AAB
  - Статус: Поддерживается
  - Последняя проверка: 2026-10

- Windows
  - Минимальная версия: Windows 7
  - Архитектуры: x86, x64, ARM64
  - Формат: EXE, MSI
  - Статус: Поддерживается в основных сборках
  - Последняя проверка: 2026-10

- Linux
  - Минимальная версия: зависит от дистрибутива
  - Архитектуры: x86, x64, ARM64
  - Форматы: AppImage, Flatpak, DEB, RPM
  - Статус: Поддерживается для основных дистрибутивов
  - Последняя проверка: 2026-10

## 11. Политика поддержки

- Поддержка платформы считается действительной только после сборки, запуска и проверки.
- Формат распространяемого файла должен быть указан явно.
- Для старых ОС используются отдельные совместимые сборки и зависимости там, где это необходимо.
- Поддержка новых ОС добавляется только после проверки API, зависимостей и безопасности.
- Поддержка платформы не гарантируется без подтверждённой сборки и тестирования.

## 13. Примечание о безопасности и совместимости

Поддержка старых ОС допустима только в рамках безопасной и стабильно работающей сборки. Не стоит обещать совместимость с платформой, если она не была собрана, запущена и проверена на ней. Для будущих версий ОС должны предусматриваться проверка совместимости и обновление зависимостей до релиза соответствующей ОС.
